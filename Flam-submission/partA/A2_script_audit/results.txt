BUG 1: lowercasing changes English but not Hindi
==============================================================================
fertility.py        : line = line.lower()
fertility_fixed.py  : (line removed; text is tokenized as written)
What the bug did    : "NASA and ISRO announced a joint mission update." -> 11 tokens lowercased, 10 as written; Hindi has no capitals
What the fix does   : both languages are measured exactly as written
Effect on the report: Hindi / English  5.9285 with the bug  ->  6.1137 fixed  (the bug lowered it by 0.1852)
                      English fertility 1.2692 -> 1.2308 (bug inflated it 3.1%); Hindi 7.5246 both times

==============================================================================
BUG 2: a double space is counted as a word
==============================================================================
fertility.py        : words = line.split(" ")
fertility_fixed.py  : words = line.split()
What the bug did    : "Please keep the books  in the cupboard." -> 8 words, one of them empty
What the fix does   : same line -> 7 words
Effect on the report: Hindi / English  6.0922 with the bug  ->  6.1137 fixed  (the bug lowered it by 0.0215)
                      Hindi fertility 7.4032 -> 7.5246; too many words made it look lower

==============================================================================
BUG 3: per-line ratios are averaged
==============================================================================
fertility.py        : return sum(per_line_fertility) / n
fertility_fixed.py  : return total_tokens / total_words
What the bug did    : a 4-word line counted as much as a 12-word line
What the fix does   : every word counts once
Effect on the report: Hindi / English  6.0925 with the bug  ->  6.1137 fixed  (the bug lowered it by 0.0212)
                      English fertility 1.2472 -> 1.2308; Hindi 7.5985 -> 7.5246

==============================================================================
ALL THREE BUGS TOGETHER
==============================================================================
Hindi / English  5.8871 (fertility.py)  ->  6.1137 (fertility_fixed.py)  = +0.2266, or 3.8%
The bugs are real but small.

==============================================================================
CONCEPTUAL PROBLEM: tokens per word is the wrong unit across languages
==============================================================================
fertility.py        : reports tokens per word
fertility_fixed.py  : also reports tokens per sentence
What is wrong       : a word is not the same amount of meaning in every language
Measured on         : the A1 corpus, 1,012 parallel sentences, gpt2

    lang    x English per word  x English per sentence     per word is
    hin                   6.34                    7.42        15% too low
    tam                  20.28                   15.54        31% too high
    tel                  16.77                   12.97        29% too high

Same text, same tokenizer, same run; only what is divided by differs.

==============================================================================
LOOKS SUSPICIOUS, IS FINE
==============================================================================
1. NFC normalisation:  line = unicodedata.normalize("NFC", line)
   Why suspicious : it rewrites the text before measuring it
   Measured       : with it 6.1137, without it 6.1137; no number changes
   In the fix     : kept

2. random.seed(1337)
   Why suspicious : it suggests the numbers depend on random sampling
   Measured       : random appears only at line 21: import random and line 25: random.seed(1337)  # reproducibility; nothing draws a random number
   In the fix     : removed, since it does nothing
